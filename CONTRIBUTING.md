# Contributing to TriSync

Bug reports, small fixes, documentation improvements, and focused regression
tests are welcome. For a larger feature or refactor, open an issue first so we
can agree on the scope. A useful bug report includes the Blender, Unity, and
URP versions, reproduction steps, the expected result, and relevant logs.

## Source layout

- `blender_addon/blendersync_vnext/`: Blender add-on and bundled dependencies.
- `blender_addon/blendersync_vnext/native/blendersync_native/`: optional Rust
  mesh extractor.
- `unity/TriSync/`: Unity Editor companion, shaders, and asset metadata.
- `tests/python/` and `tests/unity/`: Python regressions and Unity EditMode tests.
- `tools/` and `docs/`: development scripts and technical documentation.

Edit the source in this checkout, then sync it into your test installations.
Keep generated Unity assets, logs, Python caches, and local configuration out
of commits. Preserve existing Unity `.meta` files when changing assets.

## Checks without Blender or Unity

Use Python 3.11 or newer. From the repository root:

```text
python -m unittest discover -s tests/python -p "test_*.py"
```

On Windows, these source checks also run without editor installations. Install
[uv](https://docs.astral.sh/uv/) and make it available on PATH for the
compatibility-matrix script:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Test-CompatibilityMatrix.ps1 -ValidateOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Test-UnityPlayerBoundary.ps1
```

The Python tests use stubs for Blender APIs; they do not replace editor tests.
See [the testing guide](docs/TESTING.md) for focused functional checks.

## Local editor setup on Windows

Create a dedicated Unity URP test project using a matching Unity/URP pair from
[the compatibility guide](docs/COMPATIBILITY.md). The full validation script
also needs `uv`, a stable Rust toolchain, and a .NET SDK able to build the
project files generated by that Unity version. Native build details are in
[the extractor README](https://github.com/zedtiga/TriSync-OpenSource/blob/main/blender_addon/blendersync_vnext/native/blendersync_native/README.md).

Set the paths for your machine before running the examples. Replace the Unity
editor path and adjust the Blender version to match your installation:

```powershell
$unityProject = 'C:\Projects\TriSyncTest'
$unityEditor = '<full path to the matching Unity.exe>'
$blenderAddon = Join-Path $env:APPDATA 'Blender Foundation\Blender\5.0\scripts\addons\blendersync_vnext'
```

For the first Unity import, copy the companion without requiring generated
project files:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Sync-UnityRuntime.ps1 -UnityProjectRoot $unityProject -SkipProjectPatch -SkipBuild
```

Open the project in Unity, let it import, and regenerate its C# project files
from Unity's External Tools preferences. Close the project before running
EditMode tests. The companion destination defaults to `Assets\TriSync` inside
the project you selected.

Copy the Blender add-on to your chosen test installation:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Sync-BlenderAddon.ps1 -RuntimeRoot $blenderAddon
```

Enable TriSync in Blender. Restart Blender after changing loaded Python or
native code. Run the complete local validation from a clean Git checkout:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Test-Project.ps1 -UnityProjectRoot $unityProject -UnityEditorPath $unityEditor -SyncBlenderAddon -BlenderRuntimeRoot $blenderAddon -RunUnityEditModeTests
```

`Test-Project.ps1` always syncs the Unity companion and checks generated project
files. `-SkipUnityBuild` skips C# compilation only; use the source checks above
when you do not have a Unity test project. The optional stale-removal switches
delete obsolete files inside the selected TriSync installation directories.

## Submitting a change

Contributions use the license of the component being changed. The Blender
add-on, native helper, and Python/Blender tests use GPL-3.0-or-later. Original
Unity code, documentation, tools, CI configuration, and Unity tests use MIT.
Preserve the separate upstream terms for derived and vendored files; see
[the licensing overview](LICENSE.md) for the complete boundaries.

Keep each pull request focused on one problem. Explain how to reproduce it,
what changes for users, and which checks you ran. For a behavioral fix, add a
regression test where it can catch the original bug. For editor-dependent
changes, include the tested Blender or Unity/URP versions and relevant smoke
results. Describe any checks you could not run.
